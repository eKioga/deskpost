# Library Guides

**Everything in this folder is written for you — the person using the Library.** You work by talking
to the Librarian, so that is how these guides are written: what to ask for, what you will be shown,
and what you are agreeing to when you say yes. **You will not need to type a command in any of
them.**

The rest of `docs/` is design records: dated snapshots of why something was built the way it was,
written for whoever is changing the code. They are not wrong, they are just not addressed to you.

That split is the point of this folder. A guide has to stay **current**; a design record is supposed
to **freeze**. Filing them together applied the wrong maintenance expectation to both, and the
workflow guide sat two weeks stale because of it.

## Which one do I want?

| If you… | Read |
| --- | --- |
| knew the Library **before 2026-09-07** and your habits are now wrong | [Quick Start for a Returning Reader](quick-start-returning-reader.md) |
| want to **learn by doing**, safely, in a sensible order | [Learning Path](learning-path.md) |
| are **beginning a new subject** you expect to work on for months | [Starting a New Project](starting-a-new-project.md) |
| want the whole shape **as a picture** | [Workflow Guide](workflow-guide.md) |

**None of the above, and something just refused you?** Ask the Librarian — "why can't I read that?",
"what happens if I reset?", "where should this go?" It answers from the `library-help` Skill, which
knows these guides and will hand you the right one.

## In two minutes

The Library is one collection, one Shelf and one Notebook — and **one Desk per seat**. A seat is a
named place to work, bound to one Project. There is no default one, so work starts by sitting down,
which you do by answering a question rather than by running anything:

> A session that has no seat **tells you so and lists the seats**. Say which one you want, or ask
> for a new one. A conversation you resume is put back where it was, without asking.
>
> Then: **"What's on my desk?"** — your seat, what is open on it, and what is waiting for you.

Reads never need your seat's claim. Opening a Book, compiling, resetting and triaging always do.

Anything that could lose something **shows you exactly what it would do first**, and waits for one
clear yes. Your yes covers that one previewed action and nothing else.

Nothing here will destroy your work by accident. A reset **sets material aside** rather than
deleting it, and asking **"what survived the reset?"** works even in a session with no seat at all.
